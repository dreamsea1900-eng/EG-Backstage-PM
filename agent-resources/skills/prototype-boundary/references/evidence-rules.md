## 1. 輸入如何使用

不同輸入提供不同層次的資訊，但不構成 PM 開工門檻：

| 輸入 | 主要用途 |
|---|---|---|
| PM 文字／規格 | 決定要展示的功能、欄位、流程與想法 |
| 流程圖 | 決定展示步驟與主要分支 |
| 截圖／視覺稿 | 延續特定頁面的結構與資訊層級 |
| 既有 prototype | 作為本輪修改基底 |
| EG 介面版型參考 | 在 PM 未指定時補齊版型、表單排列與元件呈現 |
| examples | 對標靜態 HTML 技術品質 |

PM 不需提供 API、資料庫、request／response、錯誤碼或正式工程規格。
同一輸入若自相矛盾且會改變核心展示內容，才請 PM 指定。

## 2. 權威順序

1. 使用者本輪明確要求與修正。
2. 使用者提供的規格、流程圖與現有介面。
3. 本頁既有 prototype 與 `SCOPE.md`。
4. EG 介面版型參考。
5. 通用 Ant Design 規範與 examples。

較低層級只能補呈現方式，不能擴張較高層級的功能範圍。使用者最新修正直接生效，
同步更新 prototype 與簡短 `SCOPE.md` 即可。

## 3. 可以補什麼

### Agent 可依既有 EG 慣例自行完成

- 頁面採列表、表單、詳情或 Modal 等哪一種既有版型。
- Card、標題、表格、表單與按鈕的標準位置。
- 欄位欄數、間距、對齊、換行、尺寸與 responsive 排列。
- 展示用的合理合成資料。
- 讓 PM 指定流程可操作的最短 vanilla JavaScript。
- 同類既有介面中，完成 PM 指定動作不可缺少的最小欄位。

### 不得自行增加

- PM 沒提到的新產品能力、資料欄位或業務流程。
- 沒有依據的側欄項目、麵包屑目的地、返回按鈕或其他產品入口。
- 權限、角色、審核、匯出、批次、歷程入口與通知。
- 真實 API 分支、錯誤碼、交易回滾、補償、fallback 或重試。
- localStorage、重設 Demo、結果切換器等展示控制項。

「選擇既有版型」不是功能幻想；「因為常見後台都有，所以新增功能」才是。

## 3.1 最小完整操作

先問：使用者若操作這個控制項，畫面上是否已提供完成該動作不可缺少的資料？

- 是：實作最短驗證、loading 與結果回饋。
- 否，但 EG 有明確同類模式：使用該模式的最小欄位，標成展示假設。
- 否，且沒有可靠模式：不要放可成功提交的按鈕；改成靜態概念或停用狀態。

例如「交易」若提供確認送出，至少需要交易類型與金額；EG 既有會員錢包操作另常見備註。
不可只選交易類型便顯示成功。這些欄位讓既定操作成立，不等於新增交易功能。

## 3.2 系統行為是否顯示

- 會影響客服此刻能否操作或如何判斷：可呈現，例如「需先鎖定」、「VIP 不可降級」。
- 只在背景發生：不轉成 UI，例如寫入 Log、歷程、報表、API 回滾。
- 後續政策會影響客服決策：可用既有 Alert／說明呈現，但不得附加新的操作入口。

## 4. 何時追問

不要為了 UI 細節追問 PM。能由 EG 版型參考合理決定的內容直接完成。

只有核心功能存在互斥解讀時才問，例如：

> 這批內容同時寫了「修改既有會員頁」與「建立獨立新頁」。兩者會產生不同交付物，
> 請確認本輪是哪一種。

不要問：

> 要放在詳情頁、獨立頁，還是用 Drawer？

若只是呈現方式未指定，Agent 應直接依既有模式做出原型，並在交付時簡短說明採用的版型。

## 5. 模式分離

原型製作模式與概念探索模式要清楚區分。

探索時：

- 清楚標示每項為 `提案`。
- 說明提案解決的缺口與依據。
- 不宣稱符合既有系統。
- PM 選定想法後即可做成 prototype，不需要補 API 或工程規格。

## 6. 範例判斷

PM 寫「做一個會員搜尋頁，可依帳號和狀態搜尋並顯示結果」：

- 直接採後台「搜尋 Card＋結果 Card＋Table」版型。
- 不追問 API、分頁參數或資料庫欄位。
- 不自行增加日期、VIP、匯出或批次操作。

PM 寫「編輯會員銀行資料」但未指定呈現方式：

- 若是既有會員詳情頁上的少量欄位，採既有 Modal 表單模式。
- 使用 vertical Form、標準取消／確認與欄位錯誤位置。
- 不要求 API 契約，也不新增驗證審核或歷程入口。

PM 寫「成功寫入修改歷程」：

- prototype 可在成功結果或說明中表達「已記錄」。
- 若 PM 沒要求查看歷程，不新增歷程按鈕、列表或頁面。

PM 寫「交易包含入款、出款與額度異動」，但沒列 UI 欄位：

- 依既有會員錢包 Modal 使用交易類型、金額與備註的最小表單。
- 金額使用 InputNumber、備註使用 TextArea，值與文案標為展示用途。
- 不自行增加付款方式、優惠、審核、報表入口或 API 分支。
