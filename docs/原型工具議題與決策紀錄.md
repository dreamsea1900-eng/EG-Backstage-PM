# 原型工具議題與決策紀錄

## 2026-07-31：規格外介面與技能架構

### 已觀察問題

1. `input/README.md` 只說明可放哪些檔案，沒有說明最低內容與現有介面依據。
2. 開工流程強迫補滿 8 個槽位，AI 會先產生 Modal、Drawer、新頁等選項，再讓 PM 選擇。
3. 「不得臆測」、「對標黃金範例完整度」與「不得產骨架」互相拉扯。
4. 互動 skill 預設 localStorage、重設 Demo、結果 Radio、toast 與多分支 mock，容易產生規格外 UI。
5. 黃金範例的技術品質與產品功能界線不夠明確。
6. 共用技能實體位於 `.claude/skills`，Codex 透過 `.agents/skills` symlink 取得；
   雖非兩份內容，仍把共用規範綁在特定工具目錄與發現機制。

### 當時決策（已由後述「意圖優先原型」修正）

1. 所有共用資源遷至工具中立的 `agent-resources/`。
2. `AGENTS.md`、`CLAUDE.md` 只作入口與路由，不維護技能副本。
3. 新增 `prototype-boundary`，所有 prototype 任務優先使用。
4. 預設採嚴格製作；只有 PM 明確授權才進入概念探索。
5. 移除固定 8 槽位補完，改用證據矩陣與缺口閘門。
6. 未提及預設不在範圍，不以常見 UX 或範例補功能。
7. 每個成果頁新增 `SCOPE.md`，由 Agent 隨頁維護，不要求工程師維護全系統現況。
8. examples 只對標技術品質。

### 暫緩議題

- 是否建立可從正式前台／後台 repo 自動更新的設計資源庫。
- 是否自動抽取路由、元件、design token、畫面截圖與 API 契約。
- 共用資源如何發布、版本化與讓多個 prototype kit 更新。

上述更新機制日後獨立設計；目前不作為本 kit 可用的前提。

## 2026-07-31：PM 零安裝與驗證責任

### 已觀察問題

1. README 與 PM 操作流程要求企劃安裝 Node.js，違反靜態 prototype 工具的使用初衷。
2. workflow 直接列出 Node 驗證命令，容易讓 Agent 把環境準備與操作責任轉嫁給 PM。
3. 交付物雖是靜態 HTML，文件沒有把「直接開啟」定義成強制驗收條件。

### 本次決策

1. PM 零安裝、零終端機指令，不需 Node.js、npm、套件、build 或本機 server。
2. 成果必須能直接用瀏覽器開啟 `index.html`；CSS／vanilla JavaScript 使用
   `<link>`／`<script src>` 與相對路徑載入。
3. Node 驗證腳本只屬 Agent 內部品質工具，不是 PM 或 prototype 的執行依賴。
4. Agent 環境無法執行驗證時，必須標示未驗證並停止宣稱完成，不得要求 PM 補裝工具。

## 2026-07-31：從規格稽核改為意圖優先原型

### 已觀察問題

1. `prototype-boundary` 把防止幻想做成證據矩陣與缺口閘門，迫使 PM 先完成 UI 規格。
2. `SCOPE.md` 變成長篇簽核報告，延遲原型產出且用途不清。
3. workflow 要求補入口、狀態與 API TODO，混淆 prototype 與工程設計。
4. 現有前端本應提供視覺語言與常見版型，卻被限制成不能協助選擇呈現方式。

### 本次決策

1. PM 已描述的功能、流程與想法就是原型開工依據，不要求 API 或完整工程規格。
2. 從 `web-admin` 與 `web-casino-eg` 抽取穩定介面模式到
   `eg-interface-patterns.md`，日常製作不需重新檢索本機前端 repo。
3. Agent 可依既有模式選擇列表、表單、詳情或 Modal，並補齊欄位排列與操作位置。
4. 防幻想只限制 PM 未提到的產品能力與奇怪工程邏輯，不限制合理的 UI 呈現判斷。
5. `SCOPE.md` 改為 Agent 自用的簡短邊界，不要求 PM 簽核；輸入清楚時直接製作。
6. 工作報告只供 kit 維護者明確要求時使用，不是 PM 正常交付物。

## 2026-07-31：最小完整操作與框架邊界

### 實驗發現

1. Agent 雖不再追問 API，仍自行增加「會員查詢」導覽與無行為返回按鈕。
2. Agent 因「不得補欄位」而製作只有交易類型、按確認便成功的 Modal。
3. 銀行名稱與國碼退化成自由輸入 Input，未延續 EG 既有欄位語意。
4. 背景寫入開分洗分與交易報表被顯示成介面說明。

### 本次決策

1. 新增「最小完整操作」：可提交動作必須具備同類既有介面的最少必要輸入。
2. 必要欄位屬呈現假設，不等於新增產品能力；沒有可靠模式時不得假裝提交成功。
3. 框架外殼不得創造未提供的導覽、麵包屑、返回按鈕或死控制項。
4. 新增銀行、國碼、VIP、日期、圖片、金額與備註的既有元件映射。
5. 背景 Log、歷程、報表、回滾與補償不轉成 UI，除非影響操作者當下判斷。
6. verifier 新增上述模式的 WARN 檢查，舊實驗頁可重現 6 WARN；修正後回到 0 WARN。
