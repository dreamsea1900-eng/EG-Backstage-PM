# 通用原型邊界與設計規範

## 目的

本 kit 協助 PM 把已經想好的功能、流程與概念快速轉成可 review 的 prototype。
它會依既有 EG 前端補齊視覺與呈現方式，但不替 PM 發明新的產品能力或工程邏輯。
規範必須能長期使用，不依賴工程師每次回頭解釋前端或 API。

## 設計原則

1. PM 的功能想法決定產品範圍，不要求 API 或工程規格。
2. 既有 EG 前端決定視覺語言、常見版型、表單與回饋呈現。
3. 未提及的產品能力不加入；未指定的 UI 呈現由 Agent 依既有模式補齊。
4. 版型可以補全，產品功能不能擴張。
5. 原型製作是預設；產品概念探索必須由 PM 明確要求。
6. 探索提案與正式 prototype 分離。
7. examples 只證明技術品質，不能證明需求。
8. 每頁用簡短 `SCOPE.md` 保存防幻想邊界，不要求 PM 簽核。
9. 既有介面慣例抽成 kit 內靜態參考，日常製作不依賴本機前端 repo。
10. 可提交操作必須具有最小必要輸入；防幻想不能造成不合理的假成功。
11. 框架外殼不創造產品入口，背景工程副作用不自動轉成 UI。

## 允許自行決定

- 依功能選擇既有查詢列表、全頁表單、詳情或 Modal 版型。
- Card、表格、表單、按鈕與錯誤訊息的標準位置。
- 間距、對齊、欄位欄數、標準元件尺寸與 responsive 排列。
- 足以展示 PM 想法的中性合成資料與最短互動。
- EG 同類既有操作中不可缺少的最小欄位，並標記為展示假設。
- HTML/CSS/JS 拆檔、註解與基本可用性。

## 不得自行增加

- PM 沒提到的新欄位、產品流程或能力。
- 沒有依據的側欄項目、麵包屑、返回按鈕與死控制項。
- 權限、角色、審核、批次、歷程入口、匯出與通知。
- API 分支、錯誤碼、網路中斷、重試、回滾、補償與 fallback。
- 將背景 Log、歷程或報表寫入包裝成可見提示。
- mock 分支、Demo Radio、localStorage 與重設控制。

## 新頁與改頁

### 修改既有頁面

有現有截圖、prototype 或 HTML 時延續其結構；沒有時依 EG 既有版型完成，
但不宣稱像素級還原特定舊頁。

### 全新頁面

只要 PM 說清楚要展示的功能即可開始。Agent 依 `eg-interface-patterns.md` 選擇最接近的
既有版型，不要求 PM 先畫頁面骨架。

## 對焦方式

UI 呈現細節由 Agent 依既有模式決定。只有輸入互相矛盾，且不同解讀會改變核心功能時
才追問一個最小問題。

## 追溯

每頁 `SCOPE.md` 只簡短記錄：

- PM 想展示的內容
- 採用的 EG 既有版型
- 展示互動
- 刻意未加入的產品邏輯
- 純展示假設

使用者最新要求優先，直接同步更新 prototype 與 SCOPE。
