這是**開工模式**（從零產出新頁面）。規格來源可為**下方 `$ARGUMENTS`**，或**`input/` 內的檔案**
（圖＋md，數量種類不限）。貼上規格／放檔進 `input/` ＝授權進入流程；不逐次確認每個小動作，
但**對焦完成後、正式切版前必出規格確認書請 PM 確認一次**（見步驟 0.5）。規格不清楚或與專案
規範抵觸時中斷提問，**問到清楚為止**（每批 ≤5 題、可多批），不得以猜測代替提問；
製作**以對齊 `examples/` 黃金範例的完整度為第一要務**，規格未定義處才留 `TODO`，不得產骨架。

$ARGUMENTS

固定步驟：

0. **對焦環節**（一律要做；已附完整規格＝可少問，但回述與步驟 0.5 的規格確認書不可省）：
   - 規格來自 `input/` 時：讀 `input/` 內**所有**檔案（圖＋md，**數量種類不限**；略過 `input/README.md` 本身），綜合理解，**不假設「一檔＝一頁」**
   - 用幾句話**回述我讀到的理解**，逐一列出各檔角色（流程／規格／視覺參考…），讓 PM 抓誤讀／漏檔
   - **只問文件沒交代清楚的缺口**，以「選項確認」作答（定義見 `AGENTS.md`〈工具對應〉；每題附最佳猜測預設）；
     依下列 8 槽位挑「未解」者發問，**每批 ≤5 題、可多批，問到無未解為止**（不得以猜測代替提問）：
     ①範圍（幾頁／先做哪頁，多頁才問）②頁面骨架（列表／表單／詳情／儀表板／精靈）
     ③主要操作（新增／編輯／刪除／查看／批次／匯出／上下架／審核，多選）
     ④新增·編輯呈現（Modal／Drawer／換頁）⑤必要狀態（空／載入／錯誤／成功／無權限，多選）
     ⑥參考圖角色（1:1 復刻／版位參考／概念參考）⑦互動深度（純視覺／關鍵可點／完整假資料）
     ⑧待定項（文案／欄位／API 有無未定要留 `TODO`）
   - 把 PM 的答案併入規格，作為後續步驟的依據
0.5 **規格確認書**（對焦後、正式切版前必做；規則見 `AGENTS.md`〈開工自動流程〉步驟 4）：
   把整份規格整理成一頁摘要——8 槽位最終值、所有﹝推測﹞假設、將留 `TODO` 的未定項、
   **預估 token %**（基準見 `AGENTS.md`〈工具對應〉）——以「選項確認」發問（執行／取消）；
   PM 選「執行」＝同意整份規格，才進入下列製作步驟；取消或提修正 → 併入後重出確認書。
1. **解析規格**：
   - 【規格】／【建議】分流：【規格】必守，【建議】依專案規範取捨並在交付摘要說明
   - 整理 user flow 的狀態與分支清單（含邊界情境），作為互動實作與驗收對照的底稿
   - 比對 `antd-static-layout`、`antd-proto-interactions`，列出抵觸／缺漏——有就先問
   - 規格未定義的文案／API／常數／清單一律留 `TODO` 註記，不臆測
2. **建資料夾腳手架**：`<PascalCase頁面名>/`——
   `css/antd.css` 由 `.claude/skills/antd-static-layout/assets/antd.css` 複製、
   `js/tailwind-config.js` 用 antd-static-layout §2 固定內容、`css/base.css` 最小全域設定；
   其餘 css／js 依區塊拆檔規劃（後續修改只讀小檔）。
3. **切版與互動**：**先讀 `examples/` 黃金範例**，產出的完整度／元件註解深度／react-icons 標註／
   mock 真實度／模組化要對齊它（對標品質維度，非照抄版面）。切版遵循 `antd-static-layout`
   （元件註解＋react-icons 標註＋variant class）；互動與 mock 遵循 `antd-proto-interactions`，
   **起手先複製其 `assets/` 模板**（toast／modal／demo-radio）再改前綴；
   文案用規格中文；demo 專用控制項一律註記「轉 Figma 時忽略」。
4. **驗證**：`node .claude/skills/antd-verify/scripts/verify.js <頁面資料夾>` 跑到 0 ERROR／判讀 WARN；
   有 JS 加跑 `node --check`。
5. **交付摘要**（固定格式）：
   - 檔案清單、TODO 清單、沿用／新建元件說明
   - **驗收條件對照表**：規格的每條驗收條件 ↔ 實作位置（檔案／區塊）與達成狀態
   - **本次依據**：讀了哪些 `input/` 檔 ＋ 對焦問答的關鍵決定（讓 `input/` 清空後仍可追溯這一版）
   - **寫工作紀錄**：把本輪紀錄 append 至 `<頁面名>/WORKLOG.md`（無檔則建立；entry 格式見
     `AGENTS.md`〈工作紀錄〉，每輪 ≤15 行）
